# Documentation drift detection

The **Documentation Drift Detection** workflow audits the documentation against the
implementation each week and proposes corrections as a draft PR.

## How it works

- The source of truth is `.github/workflows/docs-drift.md`, a
  [GitHub Agentic Workflow](https://github.github.com/gh-aw/). The compiled
  `.github/workflows/docs-drift.lock.yml` is generated by `gh aw compile`; don't edit it by
  hand.
- It runs weekly and can be run manually. It uses Gemini (`gemini-3.5-flash-lite`) through the
  existing `GEMINI_API_KEY` secret.
- The job has read-only `contents` and `pull-requests` permissions. The only write is the
  `create-pull-request` safe output: one draft PR titled `[docs] ...`, limited to
  `README.md` and the Markdown under `docs/` (not `docs/historical/`). Source, tests,
  workflows and dependencies can't be changed by it.
- A correction needs a documentation statement, contradicting implementation evidence with
  file and line, and no disagreement between code and tests. Uncertain or conflicting
  findings are listed under "Needs human review" in the PR rather than edited.
- If nothing clear is found, the run ends with a no-op. Nothing is merged automatically.

## Running it manually

Actions → **Documentation Drift Detection** → **Run workflow** on `main`, or:

```bash
gh workflow run docs-drift.lock.yml --ref main
```

A PR created with the default `GITHUB_TOKEN` does not trigger CI, so run the checks
yourself (for example by pushing a commit to its branch) before treating it as ready. Review
any draft PR as normal: check each cited piece of evidence and that only
documentation changed.

## Changing it

Edit `.github/workflows/docs-drift.md`, run `gh aw compile`, and commit both files. The
Upgrade gh-aw workflow keeps the compiler version current.
